# 改造清单（做完这些，项目才算你的）

> 骨架只是起点。下面每一条都是面试会被问到的东西，做完打勾。
> 判断标准：**关掉 AI，你能不能不看代码讲清楚、并且现场改一个功能。**

---

## 1. 画出架构图（不看代码）

在纸上或 README 里画出：浏览器 → Nuxt 服务端路由 → DeepSeek → 流回浏览器。

**自检**：能说清「为什么 Key 不能放前端」「为什么流式要透传」。

---

## 2. 换一个模型跑通

把 `.env` 里的 provider 换掉（例如换成通义千问 / 智谱 / 本地 Ollama），不改业务代码跑通。

**收获**：理解「模型是可替换的依赖」，面试时能讲多模型适配。

---

## 3. 自己加一个功能（至少一个）

任选：
- 多轮对话的「删除某一条消息后重新生成」
- 系统提示词（System Prompt）可配置
- 对话导出为 Markdown
- Token 用量统计和成本估算
- 移动端适配优化

**要求**：自己写，不要复制骨架代码。

---

## 4. 自己制造并解决 3 个 bug

建议刻意制造：
- 流式输出中途断网 → 看前端怎么报错、怎么恢复
- 连续两次点击发送 → 看有没有并发问题
- Key 错误 / 余额不足 → 看错误提示是否友好

**收获**：面试问「你遇到过什么坑」，你就有真实素材。

---

## 5. 改 3 版 Prompt，记录指标变化

准备 10 个固定问题，每次改 prompt 后跑一遍，记录：
- 回答质量（主观 1-5 分）
- 平均字数
- 平均响应时间

做成一张表放进 README。

**收获**：这就是最小版本的「评测体系」，本身就是加分项。

---

## 6. 自己写 README

不能照抄骨架里的 README，要写：
- 你为什么选 Nuxt 而不是 Vue + Express
- 你踩过的坑
- 你改了什么、指标如何变化

---

## 7. 录 2 分钟视频

讲给一个不懂技术的朋友听，他能听懂「这个应用是干嘛的」。

---

## 8. 终极测试（分水岭）

**关掉 AI，从零新建一个 Nuxt 项目，做一个能流式对话的最小版本，60 分钟内完成。**

- 做到 → 这个项目是你的，可以写进简历
- 做不到 → 回到第 1 条重来
